# MeshDock 需求说明

> 暂定名 **MeshDock**（沿用 ClaudeDock、VenvDock 的命名），名字可改。
> 一句话定位：给自建 Headscale 组网用的 **中文图形客户端**，让人一眼看懂“每台设备连上了没有、走的是哪条路、快不快”，并把常用操作做成按钮。
> 编写日期：2026-10-17。背景来自 `F:\AI\mywork\mycloudserver` 的运维记录（`servers/自建组网.md`）。

## 1. 背景与原则

- 官方 Tailscale 的 Windows 托盘程序是**闭源**的，只有英文，信息也少（看不出直连还是中继）。第三方汉化版要替换官方客户端，风险大，不采用。
- 本工具**不修改、不替换官方客户端**，只调用官方命令行 `tailscale.exe`（`C:\Program Files\Tailscale\tailscale.exe`），读取结果后用中文展示。官方客户端照常自动升级。
- 第一阶段只在家里的台式机（lan-desktop）上用；工作笔记本是公司电脑，稳定之前不装。

## 2. 运行环境

| 项目 | 要求 |
|---|---|
| 系统 | **Windows 10 22H2（19045）**，三台 Windows 都是 Win10，不能依赖 Win11 才有的效果（如 Mica） |
| 官方客户端 | Tailscale 1.102.4（当前版本），控制端为自建 Headscale `https://203.0.113.1:8443` |
| 技术栈（建议） | Tauri 2 + pnpm + Vue 3 或 React（与 VenvDock / ClaudeDock 一致）；后端用 Rust 调用 `tailscale.exe` |
| 依赖 | WebView2（Win10 一般自带，安装包里要处理缺失的情况） |
| 权限 | 读取状态**不需要管理员**；修改设置如果需要提权，要先实测再决定（见第 7 节） |

## 3. 数据来源（已在本机核实可用）

| 需要的信息 | 命令 | 关键字段 |
|---|---|---|
| 设备列表、在线状态、连接路径 | `tailscale status --json` | `Self`、`Peer.*`：`HostName`、`TailscaleIPs`、`OS`、`Online`、`Active`、`CurAddr`、`Relay`、`LastSeen`、`LastHandshake`、`RxBytes`、`TxBytes` |
| 本机网络体检 | `tailscale netcheck --format=json` | UDP、IPv4/IPv6 公网地址、`MappingVariesByDestIP`（是否对称型 NAT）、端口映射、各中继延迟 |
| 实测路径和延迟 | `tailscale ping -c 1 <IP>` | 输出 `via DERP(...)` 是中继，`via 地址:端口` 是直连，以及毫秒数 |
| 本机设置 | `tailscale debug prefs` | `RouteAll`（即 accept-routes）、`ExitNodeID`、`ControlURL` |
| 修改设置 | `tailscale set --accept-routes=true/false` | — |

**连接方式的判断规则**（界面上的核心信息）：

| 条件 | 显示 | 颜色建议 |
|---|---|---|
| `CurAddr` 是 192.168.x / 10.x / 172.16–31.x | **局域网直连** | 绿 |
| `CurAddr` 是 IPv6（带方括号） | **IPv6 直连** | 绿 |
| `CurAddr` 是公网 IPv4 | **公网直连** | 绿 |
| `CurAddr` 为空，`Relay` 有值，设备在线 | **中继（经 广州）**，并提示“速度受广州 4Mbps 限制，约 500 KB/s” | 橙 |
| `Online=false` | **离线**，显示“最后在线 X 小时前” | 灰 |
| 刚开始通信、先中继后直连 | **正在打洞**（中继几秒内变直连属正常） | 黄 |

`Relay` 的值 `headscale` 显示为“广州”。

## 4. 功能需求

### P0：第一版必须有

1. **托盘图标**：颜色反映整体状态（已连接 / 未连接 / 控制端连不上）；右键菜单是中文：打开主界面、刷新、在家模式 / 出门模式、退出。
2. **主界面：设备列表**。每台设备一张卡片：名称、组网 IP、系统图标、在线状态、**连接方式徽标**（第 3 节规则）、最近延迟、收发流量、最后在线时间。本机单独放在最上面。
3. **一键测速**：每台设备一个“测试”按钮，调用 `tailscale ping`，显示实测路径和延迟。还要有“全部测试”按钮。
4. **本机网络体检**：展示 netcheck 结果，并翻译成人话，例如：
   - “你的 IPv4 是对称型 NAT，和外面的设备基本打不通，需要靠 IPv6 或中继”
   - “当前网络有 IPv6，可以和家里直连”
   - “到广州中继的延迟 20 ms”
5. **在家 / 出门模式**（accept-routes 开关）：
   - 在家 = `accept-routes=false`，出门 = `true`，界面写清楚各自的作用。
   - 显示当前实际值（从 `debug prefs` 读取）。
   - **在家时误开会让本地流量绕进隧道**（2026-09-20 踩过的坑），这种情况要醒目提示。
6. **复制 IP**：点击设备的 IP 即复制。
7. **自动刷新**：默认每 10 秒刷新状态；`ping` 只在用户点击时执行，不定时自动跑。
8. **全中文界面**，状态说明面向不懂网络的人。

### P1：第二版

1. **自动识别在不在家**：默认网关是 `192.168.66.66` 就是在家。和当前模式不一致时弹提示，默认**不自动修改**。（2026-10-20 调整：增加可选的“自动切换在家 / 出门模式”，默认关闭，开启后只在位置变化时切换一次，手动改的模式保留到位置再次变化。）
2. **路径变化通知**：某台设备从直连掉到中继（或反过来）时，发 Windows 通知。
3. **快捷连接**：设备卡片上加“SSH”“RustDesk”按钮。SSH 直接打开终端执行 `ssh <别名>`；RustDesk 用组网 IP 直连。
4. **延迟历史**：每台设备最近 24 小时的延迟和路径小图（只存本机）。
5. **主题**：跟随系统浅色 / 深色，也可以手动切换。
6. **开机自启**（可选，默认关闭）。

### P2：以后再说

- 连接 / 断开组网（`tailscale up/down`）。**风险**：断开会切断正在经组网登录这台机器的 SSH 会话，要二次确认。
- 子网路由器（手机 phone-router）的健康状态，比如它有没有 IPv6。
- 导出诊断报告（status + netcheck + prefs 打包成文本，方便发给运维）。

## 5. 界面与美化

- 风格：参考 Windows 11 Fluent 设计（圆角卡片、柔和阴影、清晰层级），但要在 Win10 上效果一致。
- 主色清爽，状态色固定为 绿=直连、橙=中继、灰=离线、黄=打洞中、红=错误，全局统一。
- 窗口约 960×640，可缩放；设备多时卡片自动换行。
- 关闭窗口时最小化到托盘，不退出。
- 中文字体优先 `Microsoft YaHei UI`，数字和 IP 用等宽字体。
- 空状态、加载中、出错都要有友好的画面，不出现原始英文报错（原文可折叠查看）。

## 6. 非功能需求

- **安全**：不保存任何密钥、Token；不启动网络监听端口；只调用官方 CLI，不改官方客户端的文件和服务。
- **性能**：常驻内存尽量 < 100 MB，空闲时 CPU 接近 0。
- **容错**：`tailscale.exe` 不存在、服务没运行、控制端连不上、命令超时（设 10 秒），都要给出中文说明。
- **兼容**：Tailscale 升级后 JSON 多出或缺少字段时不能崩溃，缺失的字段显示“未知”。
- **打包**：单个安装包（NSIS/MSI），有图标、版本号，提供卸载。
- **维护**：独立 git 仓库，README、CHANGELOG 用中文，代码注释用中文。

## 7. 动手前要先验证的问题

1. 普通权限下执行 `tailscale set --accept-routes=...` 是否被拒绝？Windows 上要看当初是谁执行的 `tailscale up`（operator）。如果需要管理员，要设计成只在切换时弹 UAC。
2. `tailscale ping` 在设备离线时要等多久超时，需要设上限，避免界面卡住。
3. `tailscale status --json` 在官方 1.102 → 1.104 之间字段有没有变化。
4. 托盘图标在 Win10 上的显示效果（Tauri 2 tray API）。

## 8. 验收场景（都是这几天真实遇到过的情况）

| 场景 | 期望显示 |
|---|---|
| ming-pc 和台式机都插网线、同在家里局域网 | ming-pc 显示 **局域网直连**，延迟约 1 ms |
| ming-pc 连有 IPv6 的手机热点 | 先显示 **正在打洞 / 中继**，几秒后变成 **IPv6 直连**（约 47 ms） |
| 工作笔记本连随身 Wi-Fi（没有 IPv6） | 显示 **中继（经 广州）**，并提示速度上限约 500 KB/s、原因是没有 IPv6 |
| 某台设备关机 | 显示 **离线**、最后在线时间，测试按钮置灰或提示离线 |
| 在家却开着 accept-routes | 醒目提示“在家应关闭子网路由”，一键改回 |
| 本机 netcheck | 正确识别：家里有 IPv6、IPv4 不是对称型 NAT、到广州中继约 20 ms |

## 9. 不做的事

- 不汉化或替换官方客户端，不做 Tailscale 的二进制补丁。
- 不做账号登录、注册新设备（加设备仍按 `servers/自建组网.md` 的流程，在广州批准）。
- 不管理 Headscale 服务端（节点批准、路由批准仍然 SSH 到广州操作）。
- 不使用 “Tailscale” 作为产品名或图标，避免商标问题。
